三条 Hook 与 MCU 状态对应

Hook 触发时机 写入状态 MCU LED UI 显示 自动重置
PreToolUse Claude 每次执行工具前 working ■ 蓝灯脉冲 蓝色慢脉冲 + 工具名 超过 300 s → idle
PermissionRequest 危险操作需用户授权 waiting ■ 黄灯快脉冲 黄色快脉冲 超过 300 s → idle
Stop 任务完成、等待下条指令 success ■ 绿灯常亮 绿色常亮 超过 10 s → idle
（自动）无活跃会话 / 超时 idle ■ 灰灯常亮 灰色常亮 —
ℹ️ gate_hook（确认模式）是 PreToolUse 的子功能：gate 开启时， 每个工具执行前写入 pending 并阻塞 Claude， 直到 MCU 按键或 UI 点击 Yes/No 才继续。此时 UI 和 MCU LED 均显示黄色（waiting）。

1

~/.claude/monitor/state_*.json
PreToolUse / Stop / PermissionRequest 触发
2
_led_sync_thread 轮询

Yes / No 确认（gate 模式）

1
gate_hook.py 拦截工具
PreToolUse 触发，写入 pending 工具信息，Claude 阻塞等待
gate_*.json → pending: {tool, input, ...}
2
LED 变黄（waiting）
_led_sync_thread 检测到 gate pending → 覆盖状态为 waiting → MCU 黄灯
Y
Yes —— MCU button1 按下
HID IN Report 0x01 → _find_gate_to_allow() → gate decision = allow
Y

monitor_ui._on_yes() → gate decision = allow

No —— UI 点击 No
monitor_ui._on_no() → gate decision = block → Claude 收到 block 指令终止工具
6
gate_hook.py 读取决策
0.15 s 轮询间隔，allow → 返回 exit 0；block → stdout 输出 JSON block 指令

⚙️
确认模式开关

1
UI 启动时默认开启
monitor_ui 启动 → 检测到新 session → 写 gate 文件 enabled=true
gate_*.json → {"enabled": true, "pending": null}
2
UI 点击"✓ 确认模式"
badge 切换 → _on_gate_toggle() → 写 enabled=false → gate_hook 读到后直接放行所有工具
!
MCU 端暂不支持切换
当前 3 个按键均映射为 allow gate，无 block 和切换确认模式的 HID 路径

HID 报文格式

方向 Report ID 字节布局 含义
MCU → Host（IN） 0x01 [0x01, btn_mask]
btn_mask: bit0=btn1, bit1=btn2, bit2=btn3		 3 个物理按键的按下/释放状态，按键抬起时发送全 0
Host → MCU（OUT） 0x02 [0x02, win1, win2, win3]
每个值 0–3，对应 idle/working/waiting/success		 三个窗口的 LED 颜色指令，兼容带/不带 report ID 的 3/4 字节格式
